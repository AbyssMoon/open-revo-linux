# Чужие исследования той же платформы

Что известно о ноутбуках MECHREVO на TongFang GXxHRXx из сторонних работ и что из
этого полезно Open Revo. Почти всё разобрано на **MECHREVO WUJIE 14XA / Forza 14X**
(плата GX4HRXL, Ryzen 7 8845HS). Это ближайший родственник WUJIE 15X (GX5HRXG): тот же
EC IT5571, та же прошивка EC 2.12 и тот же BIOS N.1.14MRO50. На 15X всё ниже нужно
проверять — в [HARDWARE.md](HARDWARE.md) попадает только проверенное.

Адреса EC — смещения в окне `0xFED50000` (ACPI `\_SB.INOU.ECRR/ECRW`), их же
читает и пишет `uniwill_read_ec_ram` в tuxedo-drivers.

## Главное: лимит заряда в процентах

Это закрывает вопрос «почему прошивка не останавливает зарядку на проценте».
Останавливает, но с завода это сломано. Подробно и с адресами — в
[HARDWARE.md → «Лимит заряда»](HARDWARE.md#лимит-заряда); реализовано в патче
`0003-mechrevo-charge-limit.patch` и командой `openrevo limit`.

- `0x07B9` — лимит, %; `0x0742` бит 2 — EC его соблюдает.
- EC берёт лимит из `0x07B9`, только если `0x07C3` или `0x0770` равен 4 или 5. Иначе он
  смотрит на свою копию лимита в `0x087F` (хосту недоступна), а MECHREVO оставляет её
  неверной — и контроль выключается.
- Обход: на ~2 с поставить `0x07C3 = 4`. EC включит лимит и сохранит его копию; дальше
  `0x07B9` работает напрямую.
- Второй путь — прошить BIOS SlimBook N1.1.14GOS07 + EC 2.12 для той же платы: в его
  меню есть настройка лимита. В новых версиях SlimBook пункт убрали.
- В EC 2.08 ошибку частично исправили, но и в 2.12 лимит часто не работает.

## Карта регистров EC (mech-forza-control)

Из [`docs/ec-register-map.md`](https://github.com/minortex/mech-forza-control/blob/main/docs/ec-register-map.md),
названия — из констант GCUService. Что может пригодиться Open Revo:

| Адрес | Что | Заметки |
|---|---|---|
| `0x0751` | режим и вентиляторы | `0xA0` офис, `0x00` баланс, `0x10` турбо — совпадает с нашим; бит `0x40` — FanBoost (вентиляторы на максимум), бит `0x80` — свой режим вентиляторов |
| `0x0726` бит 7 | «свой» режим (Custom) | писать после `0x0751`, иначе EC сбросит |
| `0x0726` бит 3 | включение при подаче питания (AC Recovery) | |
| `0x07A6` биты 4–5 | профиль заряда | у нас уже есть; в GCU: `00` — 100%, `01` — ~80%, `10` — ~60%; бит 3 — светодиод тачпада, при записи сохранять |
| `0x07B9` | лимит заряда, % | см. выше |
| `0x07D0` | нижний порог заряда, % | работает только с модифицированной прошивкой EC |
| `0x0783`–`0x0785` | текущие PL1 / PL2 / PL4, Вт | только чтение — можно показывать в мониторинге |
| `0x0786` | цель TCC, °C (биты 0–6) и включение (бит 7) | **не писать `0x80`**: CPU застрянет на минимальной частоте |
| `0x0787` | скорость смены оборотов вентиляторов | |
| `0x078C` | подсветка клавиатуры | бит 4 — включено, биты 5–7 — уровень (`000` выкл, `001` тускло, `010` ярко) |
| `0x074E` | Fn Lock | у нас через sysfs tuxedo_keyboard |
| `0x0767` / `0x0768` | Win-lock, USB-зарядка при выключенном ноутбуке | запись / состояние |
| `0x07C5` бит 7 | вентиляторы CPU и GPU по отдельности | |
| `0x07C6` бит 2 | своя кривая вентиляторов включена | |
| `0x0F00`–`0x0F5F` | таблица кривой вентиляторов | 16 точек на вентилятор; перед записью снять бит 2 в `0x07C6`, потом поставить |
| `0x0464`, `0x046B` | обороты вентиляторов, RPM | точнее, чем 0–200 из `0x1804` |
| `0x04A2` | температура батареи, 0,1 K | |
| `0x04A6` | счётчик циклов батареи (16 бит, LE) | |
| `0x04AB` | заряд батареи, % | |
| `0x0454` | версия прошивки EC | |

Там же: режимы в GCU переключаются не только через `0x0751` — ControlCenter заодно пишет
пачку регистров (кривая вентиляторов, `0x0783`–`0x0787`); это видно в
[логе переключения](https://gist.github.com/w568w/b2fc5f9d1f4dff13efe751abec27b396) из
первого гиста. Нам пока хватает того, что делает tuxedo_io.

## Прошивка EC (ec_reverse)

- **Окна доступа к памяти EC** ([`docs/xram_host_access.md`](https://github.com/minortex/ec_reverse/blob/main/docs/xram_host_access.md)).
  Хост видит только первые 4 КиБ памяти EC, и прошивка ограничивает доступ:
  - читать можно `0x000–0x7FF` и `0xC00–0xFFF`;
  - писать — только `0x400–0x4FF`, `0x700–0x7FF` и `0xC00–0xFFF`;
  - `0x800–0xBFF` закрыто полностью (поэтому `0x087F` недоступен).

  Запись в защищённые адреса молча игнорируется, чтение закрытых возвращает `0xFF`.
  Если когда-нибудь понадобится общий доступ к EC в драйвере — ограничить его этими окнами.
- **Напряжение заряда.** EC заряжает батарею не до полного напряжения, а с поправкой на
  «износ» — подробно и с замером нашего 15X в разделе
  [«Напряжение заряда и «износ» батареи»](#напряжение-заряда-и-износ-батареи).
- **Модифицированная прошивка EC** снимает это ограничение и добавляет нижний порог
  заряда. Подписи у прошивки нет, но прошивать её без программатора SPI — риск получить
  нерабочий ноутбук.
- **Регистр `0x0490`** — источник питания. Хост может туда писать, но прошивка сама
  его перезаписывает. Использовать только для чтения.

## Напряжение заряда и «износ» батареи

По [ec_reverse](https://github.com/minortex/ec_reverse) (`docs/charging_voltage_reduction_causes.md`,
`docs/battery_aging.md`), прошивка EC 2.12. EC считает напряжение, до которого заряжать:

```text
снижение на банку = max(ступень по «стрессу», по циклам, по режиму заряда, по вспомогательному уровню)
цель EC           = базовое напряжение от батареи − число банок × снижение
```

| Адрес | Что | Формат |
|---|---|---|
| `0x030E:0x030F` | базовое напряжение от батареи, мВ | big-endian |
| `0x0522:0x0523` | цель EC, мВ | little-endian |
| `0x0438:0x0439` | напряжение батареи сейчас, мВ | little-endian |
| `0x0491` биты 7:6 | число банок: `11` — 4, `10` — 3 | |
| `0x04A6:0x04A7` | циклы (от контроллера батареи) | little-endian |
| `0x07A6` биты 5:4 | режим заряда (прошивочный профиль) | |
| `0x039D` | вспомогательный уровень | byte |
| `0x09C9:0x09CA` | «стресс»: время при ≥ 4,1 В/банку с весом по температуре | big-endian, хосту не виден |

Ступени снижения, мВ на банку (берётся наибольшая):

| | 50 | 100 | 150 | 200 | 250 |
|---|---|---|---|---|---|
| «стресс» больше | `0x10E0` | `0x1950` | `0x21C0` | `0x2D00` | `0x3DE0` |
| циклы от | 150 | 250 | 350 | 450 | 550 |
| вспомогательный уровень от | 7 | 10 | 13 | 19 | 25 |
| режим заряда | — | balanced | stationary (Health) | — | — |

Прошивочные профили заряда работают именно так: они не останавливают зарядку на проценте,
а снижают напряжение заряда. Поэтому в Windows при их смене меняется «полная ёмкость».

**Вспомогательный уровень — ошибка прошивки.** По ec_reverse, его пишет функция старения из
регистра `R7`, а обработчик прерывания INT1 использует тот же банк регистров и не сохраняет
`R7`. В итоге туда попадает мусор (`0x1B`, `0x2E`, `0x31`…), и он часто перешагивает порог
25 — EC снимает максимальные 250 мВ на банку с батареи без износа. «Стресс» тоже не
сохраняется и не обнуляется при перезагрузке EC: после полного обесточивания он может
стартовать со случайного значения.

**Замер на нашем 15X** (29.10.2026, от сети, батарея заряжена, чтение окна EC
`0xFED50000` через `/dev/mem`, только чтение):

| | |
|---|---|
| базовое напряжение | 17 800 мВ (4,45 В/банку) |
| цель EC | 16 800 мВ (4,20 В/банку) — снижение 250 мВ/банку, максимум |
| батарея в конце зарядки | 16 771–16 795 мВ |
| циклы | 121 — ступени нет |
| режим заряда | `0x07A6` = `0x00` (normal) — ступени нет |
| вспомогательный уровень `0x039D` | 26 (20 с, 40 замеров, все 26) — ступень 250 |

Значит, наши «77% здоровья» (4,9 из 6,4 А·ч) — это в основном не износ: EC не дозаряжает
батарею на 1 В из-за ошибки прошивки. «Стресс» прочитать нельзя, но для объяснения он и не
нужен. Батарея с номиналом 15,48 В (3,87 В/банку) рассчитана на высокое напряжение; на
4,20 В/банку в неё входит примерно три четверти паспортной ёмкости.

**Исправить можно только прошивкой EC.** В ec_reverse есть патч `int1-r7` (ISR сохраняет
`R7`; «предварительно проверен на железе») для образа `GXxHXxx_21.200` и утилита прошивки.
Хост изменить цель не может: `0x0522` и `0x039D` в окнах только для чтения. Прошивка EC
без программатора SPI — риск получить нерабочий ноутбук; совпадение нашего образа с
`GXxHXxx_21.200` не проверяли. В Open Revo это не встраиваем.

Полное напряжение — это не только ёмкость, но и более быстрое старение батареи. Снижение по
циклам и стрессу — нормальная защита; ошибочна только вспомогательная ступень.

## Как снять, что делает ControlCenter (первый гист)

В Windows можно включить отладку ядра (`bcdedit -debug on`) и трассировку ACPI в WinDbg
(`!amli set traceon spewon`), а лог читать через DebugView. Так видно все обращения
ControlCenter к EC (`\_SB.INOU.ECRR` / `ECRW`) — этим же способом можно проверить
на 15X то, что найдено на 14XA. Сам ControlCenter (`GCUService.exe`) написан на C# и не
обфусцирован: логика режимов — в `MyControlCenter.MyFanManager.setFanMode`.

## Что ещё можно сделать в Open Revo

По убыванию пользы:

1. Проверить лимит заряда на 15X (см. [HARDWARE.md](HARDWARE.md#лимит-заряда)).
2. Подсветка клавиатуры (`0x078C`) — вкладка «Клавиатура».
3. Обороты вентиляторов в RPM, текущие PL1/PL2/PL4, циклы и температура батареи — в мониторинг.
4. FanBoost (бит `0x40` в `0x0751`) — переключатель «вентиляторы на максимум».
5. Win-lock, USB-зарядка при выключенном ноутбуке, включение при подаче питания.
6. Своя кривая вентиляторов — самое сложное и рискованное.

Для 2–5 понадобятся новые ioctl в патче драйвера, как для лимита заряда, — только
для конкретных регистров, без общего доступа к EC.
